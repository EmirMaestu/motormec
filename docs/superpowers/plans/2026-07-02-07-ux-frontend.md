## Task UX-1: Validación inline en formularios

**Problema:** todos los formularios validan solo al enviar (`Customers.tsx:152`, etc.); el
usuario envía, falla, corrige, reenvía. Ver auditoría UX #4.

**Files:** `apps/web/src/components/form.tsx` (ya existe `FormField` con `error`),
formularios en `apps/web/src/pages/*` (Customers, Vehicles, Orders, Quotes, Finance).

- [ ] **Step 1:** El componente `FormField` ya soporta mostrar `error`. Falta calcular el error
en vivo. Adoptar un patrón simple con estado por campo: validar en `onBlur` y limpiar el error
en `onChange`. Ejemplo para el nombre requerido:
```tsx
const [errors, setErrors] = useState<Record<string, string>>({});
// input:
<FormField label="Nombre" error={errors.name}>
  <Input
    value={form.name}
    onChange={(e) => { setForm({ ...form, name: e.target.value }); setErrors((x) => ({ ...x, name: "" })); }}
    onBlur={() => { if (!form.name.trim()) setErrors((x) => ({ ...x, name: "Requerido" })); }}
  />
</FormField>
```

- [ ] **Step 2:** Aplicar a los campos clave de cada formulario: nombre requerido, patente
(usar el mismo regex del backend, ver `patente.ts` — replicar en `apps/web/src/lib/validators.ts`),
teléfono (largo mínimo), montos (>= 0).

- [ ] **Step 3:** Deshabilitar el botón de submit mientras haya errores o campos requeridos
vacíos: `disabled={mutation.isPending || Object.values(errors).some(Boolean)}`.

- [ ] **Step 4: Verificar en navegador** que el error aparece al salir del campo vacío y
desaparece al escribir.

- [ ] **Step 5: Commit.** `git commit -m "feat(ux): validación inline en formularios (nombre, patente, teléfono, montos)"`

## Task UX-2: Updates optimistas en mutaciones

**Problema:** toda mutación hace refetch completo; con latencia el usuario cree que falló y
reintenta → duplica. Ver auditoría UX #5.

**Files:** las páginas con mutaciones frecuentes (Vehicles, Orders — cambio de estado, timer).

- [ ] **Step 1:** Para el cambio de estado del vehículo y el play/pause del timer (acciones de
1 clic, alto volumen), usar el patrón optimista de React Query:
```tsx
const changeStatus = useMutation({
  mutationFn: (status: string) => api.patch(`/api/vehicles/${id}`, { status }),
  onMutate: async (status) => {
    await queryClient.cancelQueries({ queryKey: ["vehicles"] });
    const prev = queryClient.getQueryData(["vehicles"]);
    queryClient.setQueryData(["vehicles"], (old: any) =>
      old?.map((v: any) => (v.id === id ? { ...v, status } : v)));
    return { prev };
  },
  onError: (_e, _v, ctx) => { if (ctx?.prev) queryClient.setQueryData(["vehicles"], ctx.prev); },
  onSettled: () => queryClient.invalidateQueries({ queryKey: ["vehicles"] }),
});
```
Ajustar el `queryKey` al que usa cada página.

- [ ] **Step 2:** Aplicar al menos a: cambio de estado de vehículo, play/pause de timer, cambio
de estado de orden.

- [ ] **Step 3: Verificar** que el cambio se refleja instantáneo y revierte si el server falla
(probar apagando el backend un momento).

- [ ] **Step 4: Commit.** `git commit -m "feat(ux): updates optimistas en cambios de estado y timer"`

## Task UX-5: Mostrar tiempo transcurrido del timer

**Problema:** el play/pause solo togglea `isWorking`; no se ve "lleva 2h 30m". Ver UX #8.

**Files:** `apps/web/src/pages/Vehicles.tsx` (card del vehículo), quizás un hook `useElapsed`.

- [ ] **Step 1:** Calcular el tiempo transcurrido a partir de `responsibles[].workStartedAt` (o
sumando `workSessions`) y mostrarlo en la card cuando `isWorking`. Actualizar cada minuto con un
`setInterval` en un pequeño componente `ElapsedBadge`.
```tsx
function ElapsedBadge({ startedAt }: { startedAt: string }) {
  const [, tick] = useState(0);
  useEffect(() => { const t = setInterval(() => tick((n) => n + 1), 60_000); return () => clearInterval(t); }, []);
  const mins = Math.floor((Date.now() - Date.parse(startedAt)) / 60000);
  return <span>En reparación: {Math.floor(mins / 60)}h {mins % 60}m</span>;
}
```

- [ ] **Step 2: Verificar** que aparece en un vehículo con trabajo iniciado.

- [ ] **Step 3: Commit.** `git commit -m "feat(ux): mostrar tiempo transcurrido del trabajo en la card del vehículo"`

## Task UX-6: Lookup de patente con debounce mientras se tipea

**Problema:** el lookup es solo on-blur (`Vehicles.tsx:479`); sin feedback mientras escribe.
Ver UX #3.

**Files:** `apps/web/src/pages/Vehicles.tsx` y `Orders.tsx` (modales de creación).

- [ ] **Step 1:** Reemplazar el `onBlur` por un debounce (300ms) sobre el valor de la patente,
disparando el lookup cuando `length >= 6` y mostrando un indicador "buscando…" y luego
"encontrado: <marca> <modelo>" o "patente nueva".
```tsx
useEffect(() => {
  if (plate.length < 6) return;
  const t = setTimeout(() => lookup.mutate(plate), 300);
  return () => clearTimeout(t);
}, [plate]);
```

- [ ] **Step 2: Verificar** que al tipear una patente existente autocompleta sin clic extra.

- [ ] **Step 3: Commit.** `git commit -m "feat(ux): lookup de patente con debounce y feedback en vivo"`
